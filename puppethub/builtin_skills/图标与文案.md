## 图标与文案（精致感来自这里）

**界面廉价感一大半来自文案和图标**——不是配色。这份管"字怎么写、图标怎么挑"。

### 图标：只用清单里的，一功能一图标

**词汇表有 65 个图标**，够用。**不要发明名字**（不存在的图标不会报错，但会静默变空白）。

常用映射：

| 功能 | 图标 | 功能 | 图标 |
|---|---|---|---|
| 新建 / 加 | `add` `plus` | 删除 | `delete` `remove` |
| 保存 | `save` | 编辑 | `edit` |
| 刷新 / 重试 | `refresh` | 搜索 | `search` |
| 设置 | `settings` | 用户 | `user` `users` |
| 成功 | `check` `success` | 出错 | `error` `warning` |
| 关闭 / 取消 | `close` `cancel` | 返回 | `arrow_left` |
| 更多 | `more` | 排序 | `sort` `filter` |
| 上传 / 下载 | `upload` `download` | 时间 | `clock` `calendar` |

- **同一功能在同一界面只用同一个图标**——"删除"一会儿 `delete` 一会儿 `remove` 就乱了。
- **图标不单独出现**（除了纯图标按钮）：旁边最好有文字，或配 `tooltip`。
- 纯图标按钮**必须给 `tooltip`**，否则用户猜：

```puppet
add #bar button #del icon=delete tooltip="删除这一条"
```

### 按钮文案：动词开头，2–4 字

| ✗ 差 | ✓ 好 | 为什么 |
|---|---|---|
| 确定 | **保存** | 说清"确定"会发生什么 |
| 提交 | **提交订单** | 具体对象 |
| 是 | **删除** | 别让用户在"是/否"里翻译 |
| 操作 | **查看详情** | "操作"不是动词 |

- **动词开头**："保存" > "确定"，"删除" > "是"。
- **两个字最稳**（中文按钮的黄金长度）；最长别超四字。
- **危险操作说清楚**：不要"确定删除吗"，要"确定删除 **3 条** 记录吗"。

### 标签与标题：短、名词、术语统一

- **标题是名词短语**："本月支出" > "这里是本月支出的情况"。
- **同一事物全文一个叫法**：别一会儿"记录"一会儿"条目"一会儿"数据"。
  **术语表放 `DESIGN.md`**，写代码时照着抄。
- 标签**词尾不留标点**（"金额" 不是 "金额："）。冒号是排版不是文案。
- 单位**跟着数值走**："¥1,280" 而不是 "金额 1280 元"。

```puppet
add #card text #value text="¥1,280" size=24 weight="bold" fg="#0f172a"
add #card text #hint text="本月支出" size=11 fg="#94a3b8"
```

### 空状态 / 错误文案：说人话，给出路

**空状态不是"暂无数据"就完了**——要告诉用户**下一步做什么**：

| 场景 | ✗ 差 | ✓ 好 |
|---|---|---|
| 空列表 | 暂无数据 | 还没有记录，点「新建」开始 |
| 搜索无果 | 空 | 没找到「xxx」，换个词试试 |
| 出错 | 操作失败 | 保存失败：网络断了，检查后重试 |
| 加载中 | 等待 | 正在读取记录… |

- 空状态**三件套**：说明现状 + 为什么 + 怎么办（能点最好给个按钮）。
- 错误文案**不甩锅、不甩代码**：不要 "Error 500"，要 "服务器没响应，稍后再试"。

### 自查清单（改完扫一眼）

1. 用到的图标都在清单里吗？（不在的会静默空白）
2. 同一功能用了两个不同图标吗？→ 统一。
3. 纯图标按钮有 `tooltip` 吗？
4. 按钮文案是动词吗？超四字了吗？
5. 同一事物有没有多种叫法？→ 统一到一个词。
6. 空状态只写了"暂无数据"吗？→ 补齐"怎么办"。
7. 错误文案里有代码/术语吗？→ 改成用户能懂的话。
