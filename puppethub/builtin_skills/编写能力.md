## 编写能力（`write capabilities.py`）

程序里的复杂逻辑落进 `capabilities.py`——语言故意做小（无循环、无自定义函数），
所以"要绕弯的事"都在这里做。

### 最小骨架

```python
"""这一行是模块说明。"""
from puppet import capability

REQUIRES: list[str] = []          # 本模块的额外 pip 依赖（用分发名，如 "requests"）

@capability(returns="dict")
def send_mail(to: str, subject: str = "") -> dict:
    """发送一封邮件，返回 {id, accepted}。"""
    return {"id": "m1", "accepted": True}
```

用 `write capabilities.py` 块写入（**写前自动存档**，可回滚）。

### 四条硬性纪律（违反了要么不注册、要么报警）

| 纪律 | 后果 |
|---|---|
| **docstring 非空** | 它是这个工具的唯一说明书。缺失 → `CAP_NO_DOC` **错误**，能力**不注册** |
| **参数写类型注解** | 注解**就是契约**。调用方传错 → `CALL_CONTRACT` 错误，**不会**静默补默认值 |
| **返回值可序列化** | 只允许 `dict / list / str / 数字 / 布尔`。返回别的类型界面拿不到 |
| **依赖显式声明** | 模块级 `REQUIRES` 与实际 `import` 不一致 → `CAP_DEPS_MISMATCH` **警告**（防"部署机上才缺包"） |

### 装饰器与签名

```python
@capability(returns="dict")                    # 声明返回类型（写进契约表）
@capability(name="别名", requires=["requests"]) # 改名 / 声明本能力专属依赖
@capability()                                   # 最简：名字用函数名，返回类型取 return 注解
```

- `capability(fn=None, *, name=None, returns=None, requires=None)`。
- **`returns` 与 `return` 注解二选一**：`returns=` 优先；两个都没写 → 契约里是 `any`（能跑，但调用方看不出该期待什么）。
- **参数默认值可选**：有默认值的参数在契约里标 `required: false`。

### 类型名写法

注解用内置名即可（写字符串也行）：`str` `int` `float` `bool` `list` `dict`。
- `int` 与 `bool` **不互通**：`bool` 传给 `int` 参数会被拒。
- `float` 参数**接受 int**（整数提升，符合规范 04 的隐式转换）。
- 不写注解或写 `any` → 一律接受（但你就失去了"第一次就读对"的引导力）。

### 写方法的推荐节奏

1. **先看【本 app 的能力】清单**——已有能力别重写。
2. 写**纯函数**：不要依赖界面状态，输入全走参数，输出全走返回值。
3. **docstring 写清"做什么 + 返回什么形状"**——它是你下一轮读到的唯一说明书。
4. 外部调用（网络 / 文件 / 子进程）**必须能失败**——失败路径见 `能力失败处理`。

### 反例（这些不该写成能力）

- 求和 / 计数 / 取前 N 项 → **内建 `sum` / `count` / `at`**，别包一层。
- 改数据源内容 → **`remove_where` / `update_where`** 命令，不是能力。
- 纯字符串拼接 → 表达式里直接做。
