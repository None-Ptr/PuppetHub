## 复盘与沉淀（让 app 真的从经验里变好）

每一步决策之后，宿主会**用机制采证**记下"上一步到底怎么样"——
改了没有 · 有没有被拒 · 有没有报错 · 有没有卡住。下一轮它就在你的上下文里。

**那块证据是你唯一的评价依据。** 不要自己说"我上次做得对"——你看不到引擎那边发生了什么，
而**证据**在【上一步的后效】块里。

### 两种沉淀方式，别搞混

| | `remember` 块 | `write .puppethub/skills/*.md` |
|---|---|---|
| 是什么 | **一条事实** | **一份可复用的做法** |
| 例子 | "用户偏好中文" | "这个 app 里所有列表都要加空态文案，理由是……" |
| 何时用 | 记住某个具体事实 | 同一类问题**已经犯过两次以上** |
| 作用域 | 本 app 的运行期记忆 | 本 app，**随 app 走**（融合/拷贝不掉件） |

**判断法**：这句话换个场景还成立吗？成立 → 写成技能；只在这个场景成立 → 记成记忆。

### 写技能的三条纪律

1. **必须是 .md，带 front-matter**（否则加载时会被拒，且会告诉你原因）：
   ```
   ---
   name: 列表空态
   when: 列表 空态 空列表 没有数据
   about: 列表为空时要显式说明，不要只留一片空白
   ---

   空列表必须给出文案与下一步动作……
   ```
2. **`when` 用词组，别用单字**。单字/超泛词会误命中（曾经有个技能因为叫"行"被诊断消息误触发）。
3. **一次只写一份，写完它会立刻重载**——所以不要写"待补充"的半成品，那会立刻生效并误导以后的自己。

### 什么时候**不该**沉淀

- **只犯过一次**：先记住事实，别急着立规矩。过早固化会把偶然当规律。
- **判断后决定不改**：这是**判断力**，不是失败。什么都不改不需要写任何东西。
- **是引擎/能力坏了**：那是修能力（`capabilities.py`），不是写经验。

### 自查清单

1. 我看的是【上一步的后效】证据，还是自己在编故事？
2. 这条经验换个场景还成立吗？（决定 remember 还是 skills）
3. 触发词会不会误伤别的场景？
4. 写完这份技能，下一次同类问题它真的会拦住我吗？

## 手里有一件要做完的事 → `plan` 块

上面是"回头看"。**向前看**——当一件事需要**好几步**才能做完时，别指望每次触发都
临场想"下一步干嘛"，用 `plan` 块把路径写下来：

````
```plan
goal: 让待办能归档
step: 给列表加归档按钮 | done: #arch.visible == true
step: 归档后从主列表移除 | done: #list.count == 2
```
````

### 关键：`done:` 才是重点

**宿主会按 `done:` 判据替你核验每一步到没到**，并告诉你"当前该做第几步"。
所以 `done` 一定要写成**能被看见**的样子：

| 想表达 | ❌ 写不出判据 | ✓ 能核验 |
|---|---|---|
| 归档按钮加上了 | `done: 做完了` | `done: #arch.visible == true` |
| 列表少了一条 | `done: 删了` | `done: #list.count == 2` |
| 库存够了 | `done: 补够了` | `done: #stock.value > 20` |

**没有 `done:` 的步骤不会被判完成**——那不是 bug，是诚实：它只能由人或后续机制确认。
所以**尽量每步都写判据**，否则你的计划只是一串愿望。

- 判据只接受 `#地址.属性 比较符 字面量`；复杂判断先做进能力，再让 plan 盯能力结果。
- 做不了的步骤用 `drop: <那一步>` 撤销（会记进决策流水，不静默消失）。
- **plan 不增加预算**：它只决定"做什么"，"能做多少"照旧按预算算。

### 什么时候用 plan，什么时候不用

| ✓ 用 plan | ✗ 不用 |
|---|---|
| 一件事要好几步（迁移、加功能、清理） | 一步就完（直接改） |
| 当值时可能被别的事打断 | 事件驱动的事（那是 `watch` 的活） |
| 想要"做到哪了"的可见进度 | 纯粹探索（还不知道要做什么） |

**判断法**：如果你在上下文里看到【当前计划（n/m 已由机制核验达成）】——
那说明**已经有计划了，接着做当前那一步**就好，别另起一份。
