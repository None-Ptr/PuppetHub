## 感知盲区：点了没反应时先看这里

**盲区** = 用户做了某个动作，但程序里**既没有处理器、也没有人订阅**——
于是界面上什么也不会发生，而用户**看不到任何解释**。

```puppet
add #main button #orphan text="导出"     // 点了什么也不会发生
```

**为什么它是 agent 最有价值的输入**：它精确命中"app 没预料到的输入"。
有规则接的地方 IR 就会响应，不需要 LLM 插手；**只有空白处才需要判断**
（补规则 / 改界面 / 反问用户 / 老实说"这个按钮还没接"）。

### 排查顺序（界面上点了没反应时）

1. **有没有 `on <目标> <事件>:`**？——`on #orphan click:` 才接得住 click
2. **目标地址对不对**？——`#orphan` 写错就成孤儿节点（诊断会报 `TARGET_MISSING`，但**只在 fire 时**）
3. **控件类型对不对**？——`button` 是 `click`，`input` 是 `change` / `submit`
4. **是不是被 `disabled` 拦了**？——`set #btn disabled=true` 时引擎层直接不派发
5. **条件不满足**？——`on #go click when #name.value != "":` 里的 `when` 为假就静默跳过

> 前四条是"真的没接"，第 5 条是"接了但这次不触发"。**都要说出来**——
> 界面上不能只是"点了没反应"。

### 给用户看的说法

不要写"操作失败"或"未实现"。说清**三件事**：发生了什么 · 为什么 · 怎么办。

| ✗ 差 | ✓ 好 |
|---|---|
| 操作失败 | 导出还没接上——点「设置」里填好接收邮箱就能用了 |
| 错误 | 这个按钮暂时不做事（功能开发中） |
| unknown | 还没有能导出这批记录的能力 |

### 往 app 里补规则时

盲区补出来的规则应该是**窄的**——只接这个动作，别顺手加一堆推测逻辑：

```puppet
on #orphan click:
    set #status text="导出功能还没接上"      # 老实话
```

真要实现它，就写清楚条件与失败路径（见 `交互反馈`）。**别猜用户想要什么**——
不确定就用 ```ask``` 反问，而不是替他决定。

### 为什么这条值得你主动看

自主回路开着的时候，**盲区会自动唤醒 agent**（这是它最高性价比的感知来源：
精确命中"app 没预料到的输入"，且天然低频）。所以：

- 你看到观察流里出现「感知：交互无处可去」→ 说明用户撞上了空白，**该你补一手**。
- 用户没喊你、但日志里有这条 → 那是系统在告诉你"这里该修"，不是打扰。

### 与定时巡检的关系

盲区是"**用户撞上**的空白"，由 `定时与巡检` 里的 `watch` 补的是"**时间到了**的检查"。
两者都是唤醒 agent 的理由，判据不同：盲区**即时**（用户就在那儿等着），
状态巡检**走去抖窗口**（可能一帧来好几条）。
