## 交互反馈（让界面"活"且可信）

静态好看不算好——**用户一动，界面必须给出反应**。没反应的界面会被当成卡死。

### 状态四件套：每个可操作控件都要想全

| 状态 | 表现 | 做法 |
|---|---|---|
| **常态** | 正常样式 | 默认 |
| **忙** | 不可重复点、有进度感 | `disabled=true` + 改文案/进度条 |
| **禁用** | 条件不满足时灰掉 | `disabled=` 绑定条件 |
| **错** | 出错要说清 | `error="提示文字"` |

```puppet
add #main row #actions gap=8
add #actions button #save text="保存" icon=save disabled=#save_busy
add #actions button #cancel text="取消"

on #save click:
    set #save_busy true
    call persist with {rows: #rows} into #save_job
on #save_job done:
    set #save_busy false
```

- **忙的时候必须禁用**——否则用户狂点，产生重复提交。
- 提交类操作要有"忙"的**可见表现**：`disabled` + 文案改「保存中…」。

### 失败必须说清楚：不静默、不笼统

**"操作失败"四个字等于没说**。错误要三件事：**发生了什么 + 为什么 + 怎么办**。

```puppet
add #form input #email placeholder="邮箱" error=#email_err
add #form text #email_hint text="" fg=#dc2626 visible=false

on #email change:
    set #email_hint visible=not contains(#email.value, "@")
    set #email_hint text="邮箱要带 @，比如 you@example.com"
    set #email_err error="格式不对"
```

- 错误信息**给具体例子**，不要只说"格式错误"。
- 错误用**语义色**（`#dc2626`），且**只用在错误**——别拿红色做装饰。
- 失败后**不要清空用户输入**（重填最恼人）。

### 过渡：用 states + animate，不要硬切

值变了瞬间跳变会显得廉价。**可动画的属性**（`bgcolor` / `fg` / `size` / `opacity` / `pad` / `w` / `h` / `radius` 等）配上 `duration` 就有过渡：

```puppet
add #entry button #go text="开始" states={hover: {bgcolor: "#1d4ed8", fg: "#ffffff"}}
add #entry col #card bgcolor=#ffffff radius=12 pad=16 animate=bgcolor duration=200
```

- **过渡要短**：`duration` 150–250ms 之间，长了显得迟钝。
- `states` 里的 `hover` / `pressed` / `focus` 是**免费的好看**——交互控件都该给。
- **不要给一切加动画**：只给"状态切换"（hover、选中、展开）。满屏乱动比不动更糟。

### `visible` 切换做展开/收起，别新开窗口

轻量内容（详情、提示、高级选项）用 `visible` 原地切换，比弹窗打扰小：

```puppet
add #main button #more text="高级选项" icon=chevron_down
add #main col #advanced gap=8 visible=false
add #advanced text #note text="..." fg=#64748b

on #more click:
    set #advanced visible=not #advanced.visible
```

### 等：给进度，别干等

耗时操作要有进度感，否则像卡死：

```puppet
add #main progress #bar value=0 max=100 fg=#2563eb visible=false
add #main text #wait text="正在处理…" fg=#64748b visible=false
```

- 有总量 → `progress` 进度条；没有总量 → 至少给一句「正在处理…」。
- **等待超过一秒就该有反馈**，这是体感阈值。

### 自查清单（改完扫一眼）

1. 每个按钮的"忙"状态想了吗？能重复点吗？
2. 会失败的操作用户会看到什么？够具体吗（有例子吗）？
3. 交互控件有 `hover` 反馈吗？
4. 有没有地方值在跳变却没 `duration`？→ 补上，150–250ms。
5. 是不是给了太多动画？→ 只留状态切换。
6. 长操作有进度或等待提示吗？
